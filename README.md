# Wordle Backend

Production-oriented FastAPI backend for a Wordle-style game. Supabase is used for two things only:

- Supabase Auth issues user access tokens.
- Supabase Cloud Postgres stores all application data.

FastAPI is the trusted game engine. The frontend authenticates with Supabase, sends `Authorization: Bearer <access_token>` to this API, and this API validates the JWT, selects hidden words, evaluates guesses, updates scores, finalizes games, and produces leaderboards.

Docker is intentionally omitted for this project.

## Architecture

```text
app/
  main.py
  core/         settings, JWT verification, DB/session dependencies
  models/       SQLAlchemy 2.0 models
  schemas/      Pydantic v2 request/response models
  api/routes/   FastAPI routers
  services/     game, auth, words, scoring, stats, leaderboards
  utils/        Wordle evaluation, enums, pagination
  scripts/      seed words and generate daily challenges
alembic/        migrations targeting Supabase Cloud Postgres
tests/          unit tests plus optional Supabase integration guard
```

The backend does not use `supabase-py` as a data layer. Core reads and writes go through SQLAlchemy directly against the `DATABASE_URL` for Supabase Cloud Postgres.

## Auth Flow

1. The frontend signs the user in with Supabase Auth.
2. Supabase returns an access token.
3. The frontend calls this API with:

```http
Authorization: Bearer <supabase_access_token>
```

4. FastAPI validates the token signature with `SUPABASE_JWKS_URL` or, for legacy projects only, `SUPABASE_JWT_SECRET`.
5. The token `sub` claim becomes the authenticated Supabase user UUID.
6. The API lazily creates a matching `profiles.id` row if it does not exist.

The API never trusts the client for hidden words, guess results, wins/losses, scores, or leaderboard writes.

For local testing and Swagger UI, the API also exposes thin Supabase Auth convenience endpoints:

- `POST /auth/register`: create a Supabase Auth user with email/password.
- `POST /auth/login`: exchange email/password for a Supabase access token.
- Swagger's **Authorize** button uses `POST /auth/token` internally, so you can enter your Supabase email and password directly in Swagger UI and have the bearer token attached to protected requests.

These endpoints do not replace Supabase Auth. They call Supabase Auth and return Supabase-issued tokens.

## Setup

Use Python 3.11 or newer.

```bash
python -m venv .venv
. .venv/Scripts/activate  # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
```

Edit `.env` with values from Supabase:

- `DATABASE_URL`: Supabase Dashboard -> Project Settings -> Database -> Connection string.
- `SUPABASE_URL`: Supabase Dashboard -> Project Settings -> API.
- `SUPABASE_ANON_KEY`: Supabase Dashboard -> Project Settings -> API.
- `SUPABASE_JWKS_URL`: usually `https://<project-ref>.supabase.co/auth/v1/.well-known/jwks.json`.
- `ADMIN_USER_IDS`: comma-separated Supabase Auth user UUIDs allowed to manage words and daily generation.

Important: `DATABASE_URL` must point to Supabase Cloud Postgres. The app rejects SQLite and localhost database URLs.

## Migrations

Alembic runs directly against Supabase Cloud Postgres through `DATABASE_URL`.

```bash
alembic upgrade head
```

Create future migrations after changing models:

```bash
alembic revision --autogenerate -m "describe change"
alembic upgrade head
```

## Running

```bash
uvicorn app.main:app --reload
```

If `API_V1_PREFIX` is blank, endpoints are available at `/me`, `/games`, `/leaderboards`, etc. If you set `API_V1_PREFIX=/api/v1`, those routes move under `/api/v1`; `/health` remains unprefixed.

## Seed Words

Create a newline-delimited word list, then run:

```bash
python -m app.scripts.seed_words --file words.txt --language en
```

Generate daily challenges:

```bash
python -m app.scripts.generate_daily --date 2026-04-15 --length 5 --length 6
```

Daily challenges can also be generated by an admin token through `POST /daily/generate`.

## Example Requests

Start a classic game:

```bash
curl -X POST http://localhost:8000/games/start \
  -H "Authorization: Bearer $SUPABASE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"word_length":5,"mode":"classic"}'
```

Submit a guess:

```bash
curl -X POST http://localhost:8000/games/$GAME_ID/guess \
  -H "Authorization: Bearer $SUPABASE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"guess":"crane"}'
```

Update username:

```bash
curl -X PATCH http://localhost:8000/me/username \
  -H "Authorization: Bearer $SUPABASE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"username":"wordsmith"}'
```

Admin bulk word import:

```bash
curl -X POST http://localhost:8000/admin/words/bulk \
  -H "Authorization: Bearer $ADMIN_SUPABASE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"words":["crane","slate","trace"],"language":"en"}'
```

## Scoring

Wins score:

```text
base_score_by_word_length
+ win_bonus
+ remaining_attempts * remaining_attempt_bonus
+ daily_bonus when mode is daily
```

Defaults:

- 4 letters: 80
- 5 letters: 100
- 6 letters: 130
- 7 letters: 160
- win bonus: 25
- remaining attempt bonus: 10
- daily bonus: 20

Losses and abandoned games score `0`.

## Security Notes

- JWTs are verified server-side before profile access.
- Hidden words and `word_id` are never returned by public game responses.
- Users can access only their own games.
- Admin endpoints require the authenticated Supabase user UUID to be listed in `ADMIN_USER_IDS`.
- Guess validation, duplicate-letter evaluation, win/loss finalization, and scoring happen only in FastAPI.
- Guess endpoints include a simple per-process rate limiter. For multi-instance production deployments, replace it with Redis or another shared limiter.

## Testing

Run unit tests:

```bash
pytest
```

Default tests do not require a local database. They set a non-local placeholder Supabase-style `DATABASE_URL` and avoid connecting to it.

Optional integration tests should use an isolated Supabase project:

```bash
$env:TEST_SUPABASE_DATABASE_URL="postgresql+asyncpg://..."
$env:TEST_SUPABASE_ACCESS_TOKEN="..."
pytest -m integration
```
